# VidyaMitra

**AI-Powered Learning, Resume & Career Platform**

VidyaMitra is a full-stack web application that helps students and job-seekers prepare for interviews, analyse their resumes against real job roles, and plan their career paths — all powered by multiple AI providers and backed by AWS cloud services.

---

## Features

### For Students / Candidates
- **AI Mock Interviews** — Multi-round interview simulation (Aptitude → Coding → Behavioral) with AI-generated questions and per-answer feedback
- **FRIEDE Voice Bot** — Conversational voice-based mock interviewer powered by ElevenLabs TTS and browser Speech Recognition
- **Smart Resume / ATS Analysis** — Upload a PDF resume, get an ATS compatibility score against a target role, matched/missing skills, and company-specific JD matching
- **Resume Builder** — Build structured resumes using guided templates and export as PDF
- **Profile Analyzer** — GitHub profile + LeetCode stats + resume combined into a role-readiness score
- **Career Planner** — AI-generated career roadmaps visualised as Mermaid.js flowcharts
- **Gap Analysis** — Skill gap identification with a personalised weekly study plan
- **Skill Trends** — Live industry trend data from News API and YouTube
- **Job Board** — Browse available job listings
- **Practice Mode** — Practice aptitude, coding, and behavioral interviews separately without formal round tracking
- **Interview History** — Full history of all sessions with downloadable PDF reports

### For Admins / Recruiters / Institutions
- **Admin Dashboard** — Manage users, roles (open/closed), question banks, institutions, and platform settings
- **Bulk Resume Upload & Screening** — Upload multiple resumes, auto-rank candidates by ATS score against a target role, export results to CSV
- **Multi-Round Pipeline** — Round 1 (Aptitude MCQs) → Round 2 (Live Coding) → Round 3 (AI Behavioral Interview)
- **Automated Invitation Emails** — Send Round 2 / Round 3 selection emails via EmailJS
- **Proctoring** — Tab-switch detection, AI-answer flagging, and optional AWS Rekognition face detection
- **Institution Subscriptions** — Tiered subscription plans with Razorpay payment integration
- **AWS Usage Dashboard** — Monitor S3 storage, Lambda invocations, and estimated costs from the admin panel

## AWS Architecture

VidyaMitra integrates Amazon S3 for private resume file storage. The architecture ensures that the S3 bucket is never exposed publicly and that resume files are only accessible through short-lived presigned URLs generated by the authenticated backend.

```
User
  │
  ▼
VidyaMitra Frontend  (React / Vite — browser)
  │
  │  POST /api/aws/resume/upload  (request presigned URL)
  ▼
VidyaMitra Backend / API  (Node.js Vite plugin — server-side)
  │   • Validates authenticated session
  │   • Derives userId from server session (never from request body)
  │   • Validates file type, extension, and size
  │   • Generates presigned PUT URL via AWS SDK v3
  │
  ▼
Amazon S3  (ap-south-1)
  │   Bucket: vidyamitra-resumes-441442683103
  │   • Private bucket — Block Public Access enabled
  │   • SSE-S3 AES256 server-side encryption
  │   • Object key: resumes/{userId}/{timestamp}-{random}-{filename}
  │
  ▼
Resume stored privately in S3
```

**Download flow:**
```
Frontend  →  GET /api/aws/resume/download?key=…
          →  Backend verifies ownership (key must start with resumes/{userId}/)
          →  Generates short-lived presigned GET URL (15 min TTL)
          →  Frontend opens URL directly — file served from S3
```

**Metadata flow:**
The S3 object key (`s3_key`), content type, and file size are persisted to the application database (`resumes` table) alongside the extracted resume text and ATS analysis, so the file can always be retrieved later.

## S3 Resume Storage

- **Bucket:** `vidyamitra-resumes-441442683103` (ap-south-1)
- **Visibility:** Private — Block Public Access is fully enabled
- **Encryption:** SSE-S3 AES256 (bucket default)
- **Object key format:** `resumes/{userId}/{timestamp}-{8-char-random}-{sanitised-filename}`
- **Upload:** Frontend requests a presigned PUT URL from the backend; the file is sent directly to S3 from the browser — the file binary never passes through the Node server
- **Download:** Backend generates a presigned GET URL (15-minute TTL); access is validated against the authenticated user's ID
- **Delete:** Backend enforces that the requested key belongs to the authenticated user before calling `DeleteObjectCommand`
- **Supported formats:** PDF (`.pdf`), Microsoft Word (`.doc`, `.docx`)
- **File size:** 10 MB client-side advisory limit; the presigned URL does not enforce a server-side `Content-Length-Range` condition
- **Credentials:** Never sent to the frontend; the AWS SDK credential provider chain is used server-side only

## Setup

### Prerequisites
- Node.js 18+
- npm 9+
- AWS CLI configured (`aws configure` or `aws login` for SSO)

### Installation

```bash
git clone https://github.com/Gopal-MD/VidyaMitra-Gopal.git
cd VidyaMitra-Gopal
npm install
```

### Environment Variables

Copy the example file:

```bash
cp .env.example .env
```

Edit `.env` and fill in your values (see [Environment Variables](#environment-variables) below).

**Never commit `.env` or any file containing real credentials.**

### Database

- **SQLite (default):** No setup needed — schema is created automatically on first run.
- **Supabase:** Set `DB_TYPE=supabase` and provide `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`.

### AWS Credentials

The server uses the **standard AWS SDK credential provider chain**. You do not need to add credentials to `.env` if your AWS CLI is configured:

```bash
# Option 1 — AWS CLI profile (recommended for local development)
aws configure

# Option 2 — AWS SSO / IAM Identity Center
aws login

# Option 3 — Environment variables (e.g. AWS Academy / Learner Lab)
# Set AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_SESSION_TOKEN in .env
```

### Start Development Server

```bash
npm run dev
```

The app starts at `http://localhost:8080`. The backend API runs as part of the same Vite dev server — no separate server process needed.

### Production Build

```bash
npm run build
npm run preview
```

## Security

- **Authentication:** Bearer token sessions — tokens stored in memory + `user_sessions` DB table; validated on every API request
- **Role-based access:** Three roles — `student`, `admin`, `institution` — enforced server-side on every route
- **S3 bucket:** Private — Block Public Access enabled; no ACL on objects; no public-read
- **Presigned URLs:** Short-lived (PUT: 10 min, GET: 15 min); `ContentType` is signed into the PUT URL
- **User isolation:** S3 keys are generated server-side using the authenticated `userId`; all GET/DELETE requests validate that the requested key starts with `resumes/{authenticatedUserId}/`
- **Path traversal prevention:** Filenames are sanitised via `path.basename()` + regex; `path.posix.normalize()` used in ownership checks
- **No credentials in frontend:** All AWS SDK calls are server-side only; the frontend receives only presigned URLs, never credentials
- **Environment secrets:** All API keys, DB credentials, and AWS credentials are read from `process.env` server-side; the `.env` file is git-ignored
